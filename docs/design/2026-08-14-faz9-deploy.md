# Phase 9 — Deployment and operations (Dokploy) (2026-08-14)

## 1. Runtime image: from distroless to node:22-slim (required by K15)

Phase 0's distroless/static image carried only core; the engine (claude CLI)
requires Node. The image is now two-stage: Go build (core + oa-mcp-proxy,
static) → node:22-slim + `@anthropic-ai/claude-code` at a PINNED version
(2.1.231). Pinning is deliberate: engine behavior does not change by surprise between
deploys, and an upgrade is visible as a commit. The container runs as the `node` user;
oa-mcp-proxy sits in the same directory as core (the adapter's lookup order).

## 2. The single-replica rule made visible

PRD §4: `replicas: 1` is required — with two replicas the routine scheduler triggers every
routine twice. An explicit `deploy.replicas: 1` + warning comment was added to the compose file.
(ClaimDueRoutines' SKIP LOCKED prevents double triggering in an accident, but the
design assumption is a single replica.)

## 3. Persistence under one root: ../files/data

DATA_DIR (run workspaces, event tee NDJSON, attachments) is bound entirely to
`../files/data` — Dokploy's file root is backed up from one place.
Postgres data goes to `../files/pgdata`, dumps to `../files/backups`.

## 4. Backups: simple, auditable, documented

`deploy/backup.sh`: `pg_dump | gzip`, 14-day retention, the cron line and the restore
command are at the top of the script. There is deliberately no separate backup
service/container: on a single-user system the host cron is enough, and the failure surface is
small.

## 5. Operational visibility

- `LOG_FORMAT=json` → slog JSON handler (enabled in compose; text locally).
- `GET /api/stats?days=N` → run counts (completed/failed/expired/pending),
  total cost in USD, tokens in/out, per-bot breakdown. Token counters have been
  accumulating on runs since Phase 1; the dashboard only sums them.
- The drain chain is complete: SIGTERM → HTTP closes → `orch.Wait()` (runs) +
  `rtn.Wait()` (scheduler tick) → exit; `stop_grace_period: 60s` covers it.
  Half-finished approvals are already safe thanks to the park mechanism (§6).
